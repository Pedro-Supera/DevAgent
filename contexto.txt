# Contexto do projeto: DevAgent

## v0.2.1 — Qualidade e documentação

Esta versão traz melhorias de qualidade sem alterações de arquitetura:

- `pytest` movido para dependência opcional `dev` (não runtime)
- `python-dotenv` removido (não utilizado no código)
- Documentação de `ResultadoScanner` corrigida: é mutável, não imutável
- Novos testes de modelos em `tests/test_models.py`
- Versão 0.2.1 em `pyproject.toml`, `__init__.py`, `README.md`
  - O badge da GUI em `devagent/gui/app.py` permanecerá com v0.2.0 nesta etapa (TODO: atualizar em v0.3.0)

## v0.3.0-arch — Refatoração estrutural

Antes da implementação futura de parser AST, integração com Groq ou cache
SHA-256, a base foi reforçada com validação de modelos, exceções de domínio e
proteções contra traversal por links simbólicos. Esta etapa não implementa
nenhuma dessas funcionalidades futuras.

## v0.3.0-ast — Análise estrutural estática

- Criado `devagent/ast_analyzer.py` com `ast.parse()` e `ast.NodeVisitor`.
- O analisador identifica imports, funções, classes, métodos, decorators e chamadas,
  preservando linhas e a relação classe → métodos.
- Erros de sintaxe retornam `ResultadoAST` controlado, sem derrubar a aplicação.
- O código analisado nunca é importado nem executado.
- Adicionados 10 testes determinísticos em `tests/test_ast_analyzer.py`.

## v0.3.0-mcp-ast — Exposição MCP do analisador AST

- Adicionada a ferramenta `analisar_arquivo_python`, que recebe um caminho de
  arquivo e retorna uma estrutura serializável com o resultado AST.
- O MCP atua somente como camada de exposição: chama `analisar_arquivo` e
  converte `ResultadoAST` para dicionário, sem duplicar a análise estrutural.
- O retorno inclui imports, classes e métodos, funções, chamadas e informações
  de erros de sintaxe.
- Adicionados testes específicos da integração MCP/AST; a suíte completa passou
  com 32 testes.
- A ferramenta pressupõe uso local ou confiável; uma allowlist de raízes poderá
  ser necessária antes de exposição a ambientes não confiáveis.

## Visão geral da v0.2.1

O DevAgent é uma ferramenta para análise estrutural de projetos Python. A versão
v0.2.1 apresenta uma interface gráfica moderna, uma varredura segura de arquivos
e diretórios e uma integração com servidor MCP para disponibilizar os resultados
de forma estruturada.

O sistema foi pensado para:
- analisar uma pasta de projeto sem seguir links simbólicos para fora da raiz;
- respeitar regras do `.gitignore` e ignorar artefatos de ambiente e build;
- apresentar árvore de arquivos, estatísticas por extensão e JSON exportável;
- executar a análise em segundo plano para manter a interface responsiva;
- disponibilizar as operações principais como ferramentas MCP.

## Estrutura atual de módulos

- `devagent/models.py`: define os modelos de scanner e os modelos tipados do
  resultado AST (`ASTImport`, `ASTClass`, `ASTFunction`, `ASTCall`, `ResultadoAST`).
- `devagent/scanner.py`: implementa `ProjectScanner`, as regras de exclusão,
  leitura do `.gitignore` e a travessia segura do projeto.
- `devagent/mcp_server.py`: registra as ferramentas MCP `escanear_projeto`,
  `obter_arvore_projeto` e `analisar_arquivo_python`, com o ponto de entrada do
  servidor.
- `devagent/gui/app.py`: implementa a aplicação CustomTkinter, seleção de pasta,
  métricas, progresso, abas de resultados e log de execução.
- `devagent/exceptions.py`: define `DevAgentException`, `CaminhoInvalidoError` e
  `ErroVarreduraError` para erros previsíveis da aplicação.
- `devagent/ast_analyzer.py`: analisa estaticamente arquivos Python sem executar
  o código analisado.

## Interface gráfica

A interface é construída com CustomTkinter e usa tema escuro inspirado no estilo
visual do GitHub, com cartões, bordas discretas e cores de estado para facilitar
a leitura. A janela oferece:

- seleção do diretório a analisar;
- métricas de arquivos, diretórios, tamanho e extensões;
- abas para árvore do projeto, estatísticas e JSON;
- barra de progresso e log operacional;
- execução assíncrona da varredura em uma thread dedicada, mantendo a janela
  responsiva durante a análise.

## Testes automatizados

A suíte está localizada em `tests/` e é executada com pytest. O status atual é
de 32 testes automatizados passando, cobrindo os modelos, o scanner, raízes
inválidas, symlink traversal externo, consultas por extensão/tamanho, a análise
AST estrutural e sua exposição MCP.

Comando de validação:

```bash
venv/bin/python -m pytest tests/ -q
```

## Versionamento e colaboração

O repositório Git local utiliza a branch principal `main` e o remoto `origin`.
Alterações devem ser mantidas restritas ao escopo da tarefa, validadas antes do
commit e publicadas somente quando explicitamente autorizado.

Os commits devem incluir somente as alterações do DevAgent e usar uma mensagem
descritiva, por exemplo: `refactor: harden scanner architecture`.
