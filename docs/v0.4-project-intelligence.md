# DevAgent v0.4 — Project Intelligence

## Objetivo

Evoluir o DevAgent de uma ferramenta de inspeção estrutural para uma camada de leitura controlada de projetos, mantendo resultados determinísticos e uma superfície de ataque pequena.

## Escopo inicial

### `listar_arquivos`

- Receber um diretório de projeto já validado pela política de caminhos.
- Retornar somente arquivos dentro da raiz permitida.
- Respeitar as exclusões já usadas pelo scanner (`.git`, ambientes virtuais, caches e arquivos sensíveis).
- Não seguir links simbólicos para fora da raiz.
- Preferir caminhos relativos na saída pública.

### `ler_arquivo`

- Aceitar somente um caminho relativo ao projeto.
- Revalidar o caminho antes da leitura.
- Rejeitar diretórios, arquivos inexistentes e caminhos fora da raiz.
- Aplicar limite explícito de tamanho antes de carregar o conteúdo completo.
- Rejeitar conteúdo binário.
- Começar com UTF-8 estrito para manter o comportamento previsível.
- Não executar, importar ou interpretar o código lido.

### `analisar_projeto`

Depois das operações de leitura estarem estáveis, agregar métricas do analisador AST existente:

- quantidade de arquivos Python analisados;
- módulos/imports;
- classes;
- funções e métodos;
- chamadas identificadas;
- arquivos que falharam por sintaxe ou leitura.

## API pública

O primeiro incremento da v0.4 expõe três operações Python:

- `listar_arquivos(root_path)`: lista arquivos legíveis com metadados e caminhos relativos;
- `ler_arquivo(root_path, caminho_relativo, max_bytes=100_000)`: lê texto UTF-8 dentro da raiz com limite de tamanho;
- `analisar_projeto(root_path, max_bytes=100_000)`: agrega métricas do AST dos arquivos Python legíveis.

No MCP, as operações correspondentes são `listar_arquivos_projeto`, `ler_arquivo_projeto` e `analisar_projeto_python`.

O limite padrão inicial é **100.000 bytes**. Ele é aplicado antes da leitura e novamente após o carregamento para reduzir o impacto de alterações durante a leitura.

## Segurança

A implementação deve reutilizar a política central de caminhos em vez de criar uma segunda regra de segurança. Nenhuma operação deve permitir traversal (`..`), escape por symlink ou leitura de arquivos explicitamente excluídos.

O MCP deve expor as mesmas regras da API Python. A camada MCP não deve criar atalhos que contornem a validação existente.

## Testes mínimos

1. leitura de arquivo UTF-8 válido;
2. arquivo inexistente;
3. caminho apontando para diretório;
4. tentativa de `../`;
5. caminho absoluto fora da raiz;
6. symlink apontando para fora;
7. arquivo acima do limite de tamanho;
8. arquivo binário;
9. arquivo ignorado/sensível;
10. listagem com caminhos relativos estáveis.

## Fora de escopo

- execução arbitrária de comandos;
- edição automática de arquivos;
- agente autônomo;
- banco vetorial/RAG sem caso de uso demonstrado;
- múltiplos agentes;
- dependências externas apenas para abstração de operações simples.

## Critério de conclusão

A versão só deve ser marcada como `0.4.0` quando API, MCP, testes e documentação estiverem coerentes entre si e a suíte de testes passar integralmente.
